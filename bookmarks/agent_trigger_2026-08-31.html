結論

はい。勝手に動きます。それが本来の動作です。

私が「試してみますか？」と聞いたのは、エージェントの仕様のせいではなく、いま動いているこのセッション側の制約のためです。ご指摘のとおりでした。

自動で動く仕組み

Claude Codeはセッション開始時に、~/.claude/agents/ にある全エージェントの name と description だけを読み込みます（本文は読みません）。

そして作業中に、いまやろうとしていることが description と噛み合った瞬間、私が自分の判断で別室を立ち上げて呼びます。あなたが名前を出す必要はありません。

実際、先ほど作った時点でシステムから登録通知が来ています。すでに待機状態です。

今回 equipment-history が反応する言い回し

description にこう書いてあります。

書いた文言これで拾える発言
「前にもあったか」「バーチカルZのこれ、前にもあったよな？」
「似た事象を探して」「似たトラブル探して」
「過去の履歴を調べて」「過去の履歴どうなってる？」
「これは既存案件か新規か」「これPRD起こす？既存に足す？」
「新規PRDを起こす前の重複チェックにも必ず使う」現場報告を新規登録しようとした場面全般

だから、こう言うだけで自動で走ります。

「洗浄機バーチカルZが今朝も止まった。ログに追加しといて」
→ 新規登録の場面なので、私が先に equipment-history を呼んで重複チェックしてから登録します。

ではなぜ私は確認を取ったのか

いまのこのセッションは、「ユーザーが頼まない限りエージェントを起動しない」という設定で動いています。ブックマーク分析のような作業で、勝手に別室をいくつも立てて費用と時間を使わないための安全側の設定です。

これはセッション側の制約であって、エージェントの仕様ではありません。通常の ~/mino-sakura-hq での作業では、この制約はかかりません。

「自動」は保証ではない、という注意点

自動発動は私の判断なので、取りこぼすことがあります。落合式の記事にも「振り分けを判断しているのはAI自身なので取りこぼす」と書かれていました。

確実性やり方
◎ 確実名前を言う →「equipment-history で調べて」
○ ほぼ自動description の言い回しに近い言い方をする
◎ 確実（仕組み化）スキル側の手順書に「必ず equipment-history を使う」と書く

3番目は既に実績があります。note-article-generate スキルは、手順の中で seo-researcher エージェントを呼ぶよう書かれているので、毎回確実に走ります。

もし工程として確実に走らせたいなら

現場報告を登録する手順が固まっているなら、スキル化して、その手順の1ステップに「equipment-history で重複チェック」を明記するのが一番確実です。ブックマーク分析の推奨16番「各工程に完了条件を明文化する」と同じ発想です。

今日はまだそこまでせず、まず自動発動で使ってみて、取りこぼす場面があるかを見るのがよいと思います。
