## グループ1：ループ設計（Loop Engineering）

#9（Boris Cherny発言起点）と#6の自動化パートが該当。「プロンプトを書く」から「完了条件を決めてループを回す」への移行が今週の最重要テーマ。Closed Loop（人が枠を設計し各段階に評価ゲートを置く）が常用budgetで現実的、という主張。

### 🛠 環境改善・向上
1. [P1] **`/loop` と `/goal` を1つ試す**：あなたは既に `loop` スキルを持っている（環境内に存在）。例として「`hr-shahou-register` で新書式を1件取得→定義ファイル生成→自己チェックが通るまで繰り返す」のような**完了条件付きの小さなClosed Loop**を1本組んでみる。#9のDISCOVER→PLAN→EXECUTE→VERIFY→ITERATEの5段階をなぞる（元記事：#9）
2. [P2] **評価ゲート（VERIFY）を既存ワークフローに足す**：#9は「品質ゲート無し＝AIがドリフトする／有り＝毎回改善する」と明言。あなたの `article-reviewer`（15項目採点）はまさにこのVERIFYゲート。これを記事以外（定義ファイル・画像プロンプト等）にも展開できないか検討する（元記事：#9）
3. [P3] **worktree並列実行**：複数エージェントを同時に走らせるとファイル衝突する→git worktreeで各エージェントに隔離ディレクトリを与える。今は単発運用なので即時不要だが、Fleet型に広げる時の前提知識（元記事：#9）

### 📚 学習
4. [P2] **Open Loop と Closed Loop の違い**：Open（自由探索・トークン爆食い・予算無限向け）/ Closed（人が枠を設計・常用予算で回る）。自動化を組む前に「まずClosed、品質ゲートが固まってからOpen」という順序を頭に入れる（元記事：#9）

### 🛠 環境改善・向上
5. [P1] **不要なMCP/スキル/プラグインの棚卸し**：#6は「全部入れてる状態は遅く・不正確・トークン無駄」と指摘。あなたは現在スキル12個＋MCP多数（jina/basic-memory/playwright/context7/discord等）。`/mcp`・`/skill` で使用頻度の低いものを洗い出し、常時起動の必要が無いものを整理する。**今すぐ効果が出る最有力**（元記事：#6）
6. [P1] **Context7 を「use context7」で使う習慣**：あなたは既にcontext7 MCPを導入済み。ライブラリ調査時にプロンプト末尾へ `use context7` を付けるだけで、`generate_images.py` の google-genai など依存ライブラリのAPI誤答が減る。CLAUDE.mdの「公式確認してから実装」ルールとも噛み合う（元記事：#6）
7. [P2] **CLAUDE.mdの定期スリム化（2週に1回）**：#6は「CLAUDE.mdは毎回コンテキストに読まれるので、長いほど考える余地を奪い、重要ルールがノイズに埋もれる」と指摘。あなたのglobal CLAUDE.mdは規模が大きめ。「Claudeが言われなくてもやれること」を削る棚卸しを定期化する（元記事：#6）

### 📚 学習
8. [P3] **Ralph Loop / Code Review / Security Guidance プラグイン**：完了まで回す・PR自動レビュー・脆弱性警告。今すぐ導入ではなく「こういう公式プラグインがある」と把握しておく。導入時はCLAUDE.mdの「まとめ記事だけで実装しない／公式で裏取り」ルールを必ず通す（元記事：#6）
