## 1. 人の確認時間を減らす仕組み（Claude Code チームのコードレビュー）

元記事：1014-1018 の 3番（@ClaudeDevs・公式ブログ 2026-10-15）

記事の要点：
- Claude Code のプログラムの約9割を Claude が書いている
- 6〜9月に取り込んだ変更は2倍超、取り消し率は40%以上減った
- 読む作業の大半を機械に移し、人の時間は「人にしか判断できない所」に回した
- 人の判断が残る所：作るべきかの判断、お金・自動更新などの危険な所、証拠（試験の結果・画面）を読むこと、結果の責任
- 同じ指摘が繰り返されたら、指摘する側ではなく元（CLAUDE.md・スキル・検査）で直す
- 点検と直しの往復は3回までに抑え、それ以上は進め方そのものを見直す
- 過去の事故を問題集にして、点検の仕組みを変えるたびに全件で試す

### 🛠 環境改善・向上
1. [P1] **業務プログラムを直したあとに `/code-review` を流す**：Claude Code に最初から入っている点検（新しい会話の目で変更を読み、誤りを探す）を使う。
   - 例：販売参謀の得意先別の売上集計プログラムを直したあと、`/code-review` と入力するだけで、集計の漏れや日付の境目の誤りを指摘してもらえる
   - 承認が要る書き換えは発生しない（読むだけの点検）
2. [P2] **控え帳の叱責事例を「試験の問題集」にする**：記事の「過去の事故を毎日の試験にする」を、専務の環境に当てはめる。
   - すでに承認の確認と測らない返答には試験がある（test-approval-gate.py・test-html-gate-exempt.py）
   - これを広げ、控え帳の事例（例：10/16 推測で3回答えた件、10/21 お尋ねの分け方を無視した件）を1件1問にして、出す前の点検の仕組みを変えるたびに全件流す
   - 効果：仕組みを直したせいで、以前防げていた誤りが再発するのを防げる
3. [P2] **業務リポジトリに REVIEW.md（点検で見る所の一覧）を置く**：記事では、短い REVIEW.md に「この場所での誤りとは何か」を書いている。

4. [P2] **知りたい部分だけ解説資料を作ってもらう**：記事のチームは、仕組み全体を誰も覚えていない前提で、知りたい部分の解説をその都度 Claude に作らせている。
   - 例：「在庫の月末集計プログラムが、どの表のどの数字を使っているかを、専務向けに1枚で説明して」
   - プログラム全体を読まなくても、直す前に要点をつかめる

### 📚 学習

## 2. 「結果が良くなったか」を測る（成田悠輔氏の研究に学ぶ活用術）

元記事：1014-1018 の 1番（@kimuai08）・2番（@ai_ai_ailover・同じ記事の引用）

記事の要点：
- 測るべきは「作るまでの時間」でなく、直し・確認・作り直しを含めた全体の時間
- 「予測が当たった」「施策が効いた」「利益が良くなった」は別々に見る
- 前後で数字が違うことと、その変更が原因であることは別
- 比べるときは、同じ資料・同じ確認項目でそろえる
- 依頼の前に「目的・入力・出力・確認方法」の4行を書く
- 記事の筆者は、成田氏本人の Claude Code の使い方は公開されていないと明記している

### 🛠 環境改善・向上
6. [P1] **依頼の前に4行（目的・入力・出力・確認方法）を書く**：次に新しい集計や資料を頼むとき、最初にこの4行を添える。
   - 例（運賃の月次照合）
     - 目的：運送会社の請求額と自社の出荷記録の差を見つける
     - 入力：10月分の請求書（PDF）と出荷の一覧（エクセル）
     - 出力：差のある行だけを並べたエクセル1枚
     - 確認方法：請求書の合計額と、エクセルの合計額が一致すること
   - 4行が書けない仕事は、まだ頼む段階ではないと判断できる
7. [P2] **売上の増減を4つに分けて整理してもらう**：販売参謀に売上の変化を尋ねるとき、次の4つに分けるよう依頼する。
   - ①データで直接確かめられること ②原因の候補（未確定） ③比べにくくしている条件（同じ時期の値上げ・季節・新規の取引先など） ④次から記録すべき項目
   - 「原因を断定できなければ『断定できない』と書く」を添える
   - 効果：値上げの月と売上の増加が重なったとき、値上げが原因だと早合点するのを防げる
8. [P2] **AIに任せた業務の「全体の時間」を記録する**：日報アプリや月次集計など、Claude Code に任せた業務ごとに、準備・作成・直し・確認の時間を記録する。
   - 例：案件台帳の各案件に「直しの回数」「確認にかかった時間」を1行で残す
   - 効果：「速くなった」ではなく「本当に楽になったか」を数字で判断できる

### 📚 学習
9. [P3] **反実仮想（＝別のやり方をしていたら結果はどうなったか）の考え方**：クーポンを配った相手が、配らなくても買っていたかもしれない、という例で学べる。
   - 値引き・販促の効果を判断するときに役立つ
10. [P3] **Open Bandit Pipeline（ZOZO が公開した、推薦の方法を比べるプログラム）**：記録に「その選択がどれくらいの確率で選ばれたか」まで残す必要がある理由を、実物で学べる。
   - 研究向けで、業務にすぐ使うものではない
