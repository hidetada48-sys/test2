今日の分析で使った x-bookmark-analyze はスキルなので、分担は起きていません（だから68KBを私が直接読みました）。

Q1. あらゆる場面で勝手に立ち上がるのか

「あらゆる場面」ではありません。description に書いた条件に噛み合ったときだけです。

ただし判定しているのは私（Claude）なので、機械的な条件分岐ではありません。取りこぼすこともあれば、余計に立ち上げることもあります。ここは正直に申し上げます。

ご懸念はもっともです

私が提案した bulk-reader の description は、こう書いてありました。

「集計して」「拾って」「一覧にして」「全部から探して」「突き合わせて」
と言われたとき、対象が複数ファイルまたは数十KB以上なら必ず使う。

これはかなり広いです。「数十KB以上」は業務データのほとんどが該当するので、実際に頻繁に立ち上がります。この広さは私の設計判断であって、ご承認いただいた条件ではありません。

Q2. 立ち上がったこと・分担されたことは見えるのか

見えるもの ◯

ターミナルに、こういうブロックが出ます。

● Task(bulk-reader)
  ⎿ 薬品R08年度xlsから4〜8月の原単位を月別に抽出
    Done (6 tool uses · 41.2k tokens · 38s)
  • どのエージェントが動いたか（名前が出る）
  • 何を頼まれたか（1行の指示）
  • どれだけ使ったか（ツール回数・トークン・所要時間）

立ち上がったこと自体は必ず見えます。黙って動くことはありません。

見えないもの ✗

  • 別室の中でのやりとり（どのファイルをどう読んだか）— 既定では折りたたまれています
  • エージェントの最終報告そのもの — これはあなたには直接表示されず、私にだけ返ります

2つ目が重要です。エージェントが何と報告してきたかは、私が伝えない限りあなたには届きません。私が要約して伝えることになっているので、私の要約が挟まる＝そこで落ちる可能性があるということです。

対策：3つ、どれも今すぐ効きます

対策1：私に「必ず報告する」ルールを課す（一番簡単・確実）

グローバル CLAUDE.md に1項目足すだけです。

## エージェント使用時の報告ルール
- サブエージェントを起動したら、回答の冒頭で必ず次を書く
  「【エージェント使用】名前 ／ 頼んだこと ／ 返ってきた要点」
- 起動を見送った場合も、判断に迷った場面ではその旨を1行添える
- エージェントの報告をそのまま採用せず、
  自分で確認できる範囲は確認してから使う

3つ目は推奨7番（レビュー結果をそのまま適用させない）と同じ考え方です。下請けの報告も無検証で通さない。

対策2：description を狭くする（発動条件を握る）

運用descriptionの書き方向く人
自動任せ「〜のとき必ず使う」（今の案）まず効果を見たい
半自動「対象が5ファイル以上または100KB以上のときに使う」と閾値を上げる頻度を抑えたい
指名のみ「ユーザーがエージェント名を明示したときだけ使う」完全に手綱を握りたい

最初は「指名のみ」で作って、慣れてから広げるのが安全です。ブックマーク分析の推奨21番「1時間・1体・1業務から始める」と同じ考え方です。

対策3：起動をログに残す（後から追える）

あなたの環境はすでにフックを6種類（PreToolUse / PostToolUse / SessionStart / SessionEnd / PostCompact / UserPromptSubmit）使いこなしています。同じ要領で、エージェント終了時にログを書けます。

ただし要確認です。サブエージェント終了を捕まえるイベント（SubagentStop という名前だと認識していますが、確証がありません）は公式ドキュメントで裏取りしてから実装すべきです。CLAUDE.md の「まとめ記事やツイートの情報だけで実装しない」に該当します。
→ doc-verifier エージェントで確認できます。

おすすめの順番

  1. 対策1（報告ルール）を先に入れる — CLAUDE.md に4行。これだけで「知らないうちに分担されていた」は無くなります
  2. bulk-reader は「指名のみ」で作る — あなたが名前を言ったときだけ動く。まず挙動を見る
  3. 使ってみて有用なら、description を広げて自動発動に移行
  4. 対策3（ログ）は、自動発動に移行するときに検討

なお、今日作った equipment-history は現在「自動発動する」書き方になっています。ご希望なら「指名のみ」に狭めます。
